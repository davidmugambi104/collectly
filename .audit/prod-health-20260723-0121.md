## TOP FIXES (priority order)

### 🔴 P0 — Lead-notify email pipeline is silently broken
**`/api/lead-notify` returns 200 but `notified:false` because Resend rejects the `from` address.** Anyone submitting the waitlist form is **not getting the confirmation email** and the team is **not getting the notification email**. The error is logged but the UI tells the user "success."
- **Fix:** in the Resend `from:` field, use a verified sender — must be `Name <email@your-verified-domain>` format, sent from a domain you've authenticated in Resend (currently appears to be using an unverified or malformed `from`). Also consider surfacing a user-facing error when `notified:false` instead of returning `ok:true`.

### 🟠 P1 — Broken nav links in the production homepage
`/interview` and `/playbook` are linked in the global nav and return 404. Anyone clicking the navbar gets a "Page not found" experience on a polished marketing site.
- **Fix:** either add the missing `/interview` and `/playbook` routes, or remove them from the nav until they exist. Two-minute fix.

### 🟠 P1 — No favicon, no manifest, no apple-touch-icon, no OG image
The site has **zero** of these. Browser tabs, iOS bookmarks, PWA installs, and Slack/Twitter previews all look broken or generic.
- **Fix:** drop a `favicon.ico` + `favicon-32x32.png` (and ideally 16, 180 for apple-touch) into `public/`, add `<link rel="icon">` and `<link rel="apple-touch-icon">` in the root layout, add a `manifest.json`, and add `<meta property="og:image">` pointing to a 1200×630 preview.

### 🟡 P2 — Missing security headers
`Content-Security-Policy`, `X-Frame-Options` (or CSP `frame-ancestors`), `X-Content-Type-Options: nosniff`, `Referrer-Policy`, and `Permissions-Policy` are all absent. This is a B2B SaaS that asks customers to trust it with their financial workflows — headers should be locked down.
- **Fix:** add `headers()` in `next.config.mjs` to set CSP (start with `default-src 'self'; script-src 'self' 'unsafe-inline' https://clerk.getcollectly.app https://*.clerk.accounts.dev https://*.posthog.com; ...`), `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, and a sensible `Permissions-Policy`.

### 🟡 P2 — Add a real `/api/healthcheck`
Right now no health endpoint exists. Both `/api/integrations/sync` and `/api/dunning/public-demo` return 405 on GET, so uptime monitors can't probe them.
- **Fix:** add `app/api/healthcheck/route.ts` returning `200 {"ok":true,"version":"..."}`. Cheap.

### 🟢 P3 — Wildcard CORS on all responses
`access-control-allow-origin: *` is set globally by Vercel for static/prerendered responses. For an API endpoint that takes JSON POSTs of customer PII, you'd want to lock that down to known origins (or remove the wildcard on `/api/*`).
- **Fix:** add an explicit `Access-Control-Allow-Origin` for `/api/*` routes only if any third party actually needs CORS access. Otherwise leave as-is but be aware.

### 🟢 P3 — CORS preflight on `/api/lead-notify` doesn't echo `Access-Control-Allow-Origin`
If the waitlist form is embedded anywhere off-origin (e.g. on a marketing landing page hosted on a different domain, or inside a Vercel preview), browser POSTs will fail. The endpoint advertises `allow: OPTIONS, POST` but doesn't respond to the `Origin` header.
- **Fix:** if cross-origin is needed, add `Access-Control-Allow-Origin: <specific-origin>` (not `*`, since the endpoint accepts JSON). Otherwise document it as same-origin only.

### 🟢 P3 — `/api/exec-summary` 401 is publicly cacheable
Minor: the 401 response has `cache-control: public, max-age=0, must-revalidate` and was served from Vercel cache. Low-impact info leak, but the response shouldn't be cached.
- **Fix:** add `Cache-Control: no-store` to authenticated 401 responses.
