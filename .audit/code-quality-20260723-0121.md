## HIGH — real bugs or maintenance traps

### H1. `getEventsByType` WHERE clause is a silent boolean, not a filter
**File:** `src/lib/events.ts:67`  
**Issue:**
```ts
.where(eq(events.orgId, orgId) && gte(events.createdAt, since))
```
The `&&` is JavaScript short-circuit, returning `false | 0` — a truthy/falsy value coerced into the WHERE clause. Drizzle silently treats this as no filter, so the function returns **every event in the table**, ignoring `orgId` and `since` entirely. No error, no warning.  
**Why:** Currently no caller imports this function, so the bug is dormant — but the next time someone wires it up (e.g. for a billing reconciliation or per-type dashboard widget), every event across every tenant will be returned.  
**Fix:** Use `and()`:
```ts
.where(and(eq(events.orgId, orgId), gte(events.createdAt, since)))
```

### H2. `auth-helpers.ts` is completely dead, but looks load-bearing
**File:** `src/lib/auth-helpers.ts` (whole file, 40 lines)  
**Issue:** Exports `ensureUserAndOrg`, `ok`, `bad` — none imported anywhere. The file lives alongside the **actually-used** `auth-helper.ts` (singular) and risks being picked up by a future developer.  
**Why:** Drift trap. The next person who needs an auth helper will either (a) reach for the wrong file, or (b) duplicate the working `getAuth()` logic.  
**Fix:** Delete `src/lib/auth-helpers.ts` outright. If `ok`/`bad` response helpers are wanted, they belong in `src/lib/api-response.ts` and should be used everywhere (see M3).

### H3. XSS sink in upgrade-request email body
**File:** `src/app/api/upgrade-request/route.ts:90-92`  
**Issue:**
```ts
`<p><strong>Notes from customer:</strong><br/>${(data.notes ?? '(none)').replace(/</g, '&lt;').replace(/\n/g, '<br/>')}</p>`
```
Only `<` is escaped, not `>` or `"` or attribute-context metacharacters. More importantly, the same `data.notes` and `data.customerName` are interpolated in adjacent `<td>` cells. The replacement runs on `notes` but `customerName` is interpolated raw.  
**Why:** The notification email is sent to `LEAD_NOTIFY_EMAIL` (Davie) — an internal recipient, so impact is limited, but the pattern is wrong and will be copy-pasted.  
**Fix:** Use a tiny HTML escaper for all interpolated values, or better, render the table with a proper templating step. At minimum escape `customerName` and `org.name` too.

### H4. XSS sink in dunning/test and dunning/send HTML wrappers
**Files:**
- `src/app/api/dunning/test/route.ts:102` — `html: <p ...>${result.body}</p>`
- `src/app/api/dunning/send/route.ts:39` — `html: <p ...>${data.body}</p>`
- `src/app/dashboard/dunning/preview/route.ts:62-65` (less critical — server output only)

**Issue:** Dunning message bodies flow through `generateDunningMessage` (Gemini) and/or are user-editable in the dunning editor. The HTML wrapper interpolates the raw body inside HTML with **no escaping**.  
**Why:** A customer-facing email can be hijacked if a malicious sequence author, or a prompt-injection on the Gemini call, smuggles `<script>` or `<img onerror>` tags.  
**Fix:** Either (a) render as plain-text email (`text:` field), or (b) escape `${...}` and rely on the existing `white-space: pre-wrap` for newlines.

## MEDIUM — debt worth paying

### M1. Four near-identical OAuth connect routes
**Files:**
- `src/app/api/quickbooks/connect/route.ts` (10 lines)
- `src/app/api/xero/connect/route.ts` (16 lines)
- `src/app/api/square/connect/route.ts` (20 lines)
- `src/app/api/stripe-connect/connect/route.ts` (22 lines)

**Issue:** Same shape: `GET → read orgId → check provider env → 302 to authUrl()`. Each one is a different provider's URL builder but the surrounding boilerplate is duplicated 4×.  
**Why:** Adding a 5th provider (HubSpot? NetSuite?) means copy-pasting a 5th file. A typo in one will silently 500.  
**Fix:** Extract a `createOAuthConnectHandler({ providerName, envVars, buildAuthUrl })` factory in `src/lib/integrations/connect-handler.ts`. All four become 3-line configurations.

### M2. Four near-identical OAuth callback routes
**Files:**
- `src/app/api/quickbooks/callback/route.ts`
- `src/app/api/xero/callback/route.ts`
- `src/app/api/square/callback/route.ts`
- `src/app/api/stripe-connect/callback/route.ts`

**Issue:** Same shape: `GET → check error/code/state → call exchange → call save → redirect to ok=<provider>`. Differs only in the `exchange` function signature (Square needs the PKCE verifier) and the success URL query param.  
**Why:** Same maintainability concern as M1.  
**Fix:** Same factory pattern, parameterized by `exchangeCode` and the additional validation step (PKCE for Square).

### M3. Inconsistent error response shape across API routes
**File:** 35 API route files.  
**Issue:** Same fact expressed three ways: `{ error: 'msg' }`, `{ error: 'msg', hint: '...' }`, `{ ok: false, error: '...' }`. Some return `String(e?.message ?? e)`, others `e?.message ?? e`, others `e.message`. The `ok` field is sometimes present, sometimes absent, and has opposite meanings in `dunning/test` (where `ok: false` is non-fatal failure) vs `dunning/send` (where `ok: false` is fatal).  
**Why:** Frontend and any future SDK will need a per-route mapping table. Every new endpoint is a fresh coin-flip.  
**Fix:** Adopt one envelope: `{ ok: boolean, data?, error?: { code, message, hint? } }`. Move the helpers from the dead `auth-helpers.ts` (`ok`, `bad`) into `src/lib/api-response.ts` and use them in every route. The auth-helpers file already names them — lift and ship.

### M4. `as any` in DB proxy imports defeats the `strict: true` setting
**Files (representative):**
- `src/db/pg.ts:34` — `(getDb() as any)[prop]`
- `src/db/index.ts:11` — `export const db: any = ...`
- `src/lib/infra.ts:22-24` — `resend`, `twilio`, `stripe` proxies typed as `(t as any)[p]`

**Issue:** `tsconfig.json` correctly sets `"strict": true`, but the database proxy and infra proxies opt out, then propagate `any` to every consumer. 34 `as any` casts and 102 total `any` occurrences. The DB is `any`, so every `db.select()...` call loses its row-type inference.  
**Why:** Strict mode is supposed to catch query shape mistakes. Right now the Drizzle `NodePgDatabase<typeof schema>` type is thrown away the moment you write `db.insert(...)`.  
**Fix:** The pglite path can be a typed return — `import('drizzle-orm/pglite').PgliteDatabase<typeof schema>` — and the index can be a discriminated union or just delegate to a typed factory. The lazy proxy pattern with `any` is convenient but expensive.

### M8. Magic number `86400000` scattered in 20+ places
**Files:** forecast route, dunning test, dunning public-demo, dunning scheduler, both seed files, invoice form, dev-auth, etc.  
**Issue:** `1000 * 60 * 60 * 24` is the universal "milliseconds in a day" but appears bare, with no `MS_PER_DAY` constant.  
**Why:** Easy to typo (60 * 60 * 24 * 1000 = 86_400_000 — same, but a missing *1000 will silently produce wrong dates).  
**Fix:** Add `export const MS_PER_DAY = 86_400_000` to `src/lib/utils.ts`, swap usages. Sub-15-min change.
